# Устройство Effect-плагина: от регистрации до кадра

**Основа главы:** присланный SDK `ae25.6_61.64bit.AfterEffectsSDK`, проверка исходников 2026-09-30. Здесь разобраны объявления и официальный Skeleton, а не результаты нового запуска в AE. Идентичность источников и границы проверки — в [записи SDK 25.6](../18-SDK-HEADER-TOOLS/05-SUPPLIED-SDK-25.6.md).

Effect-плагин не является самостоятельной программой, которая сама выбирает следующий кадр. AE вызывает его обработчик с командой `PF_Cmd`; смысл остальных аргументов определяется этой командой. Поэтому первый вопрос при чтении чужого эффекта — не «где цикл по пикселям», а «какая команда привела нас в эту ветку». Источник: [A1], [A2].

## 2. Регистрация и обработчик — разные части

В этой поставке Skeleton содержит `PluginDataEntryFunction2`, которая вызывает `PF_REGISTER_EFFECT_EXT2`. Среди передаваемых сведений есть имя, match name, категория, строка имени обработчика `EffectMain` и support URL. Сам `EffectMain` расположен отдельно и разбирает `cmd`. Регистрационный вызов не является обработкой кадра. [A4]

При переименовании образца нужно согласовать его регистрационные сведения, ресурс PiPL и экспортируемый символ. Нельзя менять только имя файла `.plugin` и считать, что внутренние идентификаторы изменились. Это рекомендация по интеграции; корректность итоговой регистрации проверяется сборкой и загрузкой, а не этим текстом.

Объявление обработчика в Skeleton имеет следующий вид; экспортный макрос определяется SDK-файлом `entry.h`:

```cpp
extern "C" DllExport PF_Err EffectMain(
    PF_Cmd cmd,
    PF_InData* in_data,
    PF_OutData* out_data,
    PF_ParamDef* params[],
    PF_LayerDef* output,
    void* extra);
```

Это **объявление интерфейса**, не готовая реализация плагина. В нём нет PiPL, обработки команд или алгоритма. Сверка: [A2], [A5]. Не подставлять `...` в реальную сигнатуру и не исправлять несовпадение приведением указателя на функцию.

| Аргумент | Как его читать |
|---|---|
| `cmd` | Какую работу сейчас просит выполнить AE |
| `in_data` | Входной контекст; доступность полей зависит от команды |
| `out_data` | Ответ эффекта: параметры настройки, флаги, сообщения, данные соответствующего жизненного цикла |
| `params` | Описания/значения параметров; правила classic render и SmartFX различаются |
| `output` | В classic `PF_Cmd_RENDER` — готовый выходной image world |
| `extra` | Дополнительный контракт конкретной команды, а не универсальный произвольный объект |

Не разыменовывать `output` или приводить `extra` к SmartFX-структуре до проверки команды. Так, `PF_Cmd_ABOUT` допустим в любой момент, в том числе без подготовленного global state. [A1], [A2]

## 3. Жизненный цикл без ложной линейности

Следующая таблица — карта обязанностей, **не обещание единственного порядка вызовов**. Особенно важно учитывать повторную настройку, дублирование и сериализацию экземпляра. [A1]

| Команда | Задача эффекта | Что нельзя предполагать |
|---|---|---|
| `PF_Cmd_ABOUT` | Подготовить информацию об эффекте | Что `GLOBAL_SETUP` уже создал все данные |
| `PF_Cmd_GLOBAL_SETUP` | Проверить протокол, установить версию и применимые capabilities | Что здесь уже доступны пиксели конкретного слоя |
| `PF_Cmd_PARAMS_SETUP` | Добавить пользовательские параметры и указать их количество | Что входной параметр 0 нужно создавать самостоятельно |
| `PF_Cmd_SEQUENCE_SETUP` | Подготовить данные применённого экземпляра | Что это единственный способ появления состояния экземпляра |
| `PF_Cmd_SEQUENCE_RESETUP` | Восстановить/пересоздать sequence data | Что входные данные обязательно ненулевые; header допускает UI- и render-thread |
| `PF_Cmd_GET_FLATTENED_SEQUENCE_DATA` | Вернуть независимую сериализуемую копию | Что возвращённый handle остаётся собственностью эффекта |
| `PF_Cmd_FRAME_SETUP` / `PF_Cmd_FRAME_SETDOWN` | Подготовить/освободить classic frame-local данные | Что это замена SmartFX pre-render data |
| `PF_Cmd_RENDER` | Выполнить classic рендер | Что дополнительные layer-параметры уже загружены |
| `PF_Cmd_SMART_PRE_RENDER` / `PF_Cmd_SMART_RENDER` | Описать зависимости, затем обработать предоставленные worlds | Что это два названия для одного classic callback |
| `PF_Cmd_SEQUENCE_SETDOWN` / `PF_Cmd_GLOBAL_SETDOWN` | Завершить соответствующее владение данными | Что допускается повторно освобождать чужие buffers |

Для `GET_FLATTENED_SEQUENCE_DATA` header явно передаёт владение возвращённым handle хосту. Legacy `SEQUENCE_FLATTEN` имеет другой сценарий: заменить неплоские данные плоскими. Не переносить один способ освобождения на другой. [A1:1094–1142]

## 4. Три разных номера версии

Нужно различать версию приложения, версию effect-протокола и версию собственного продукта. В полученной поставке `AE_EffectVers.h` задаёт `PF_PLUG_IN_VERSION=13` и `PF_PLUG_IN_SUBVERS=29`; это **не версия AE 13.29**. `out_data->my_version` описывает ваш эффект и заполняется при `GLOBAL_SETUP`. [A3], [A6]

Не переписывать эти числа из старого примера без сверки. При этом сам факт использования header 25.6 не доказывает, что собранный эффект загрузится во всех версиях AE: совместимость требует отдельной матрицы и фактических проверок.

## 5. Параметры: индекс, disk ID и текущее значение

Параметр `params[0]` — входной слой, предоставляемый AE автоматически. Skeleton объявляет индексы `INPUT`, `GAIN`, `COLOR`, затем `NUM_PARAMS`; отдельно задаёт disk IDs для пользовательских параметров. `out_data->num_params` должен учитывать и неявный вход. [A3:2850–2856], [A5:77–87]

**Индекс** нужен коду для обращения к элементу массива. **Disk ID** участвует в идентификации параметра при сохранении. Даже когда числа совпадают, эти роли не следует объединять. Редакционная рекомендация для выпущенного продукта: сохранять смысл ранее использованных IDs и проверять миграцию старых проектов при изменении структуры параметров.

В classic `PF_Cmd_RENDER` обычные числовые параметры уже содержат значения текущего времени, а `params[0]` и `output` готовы для работы. Дополнительный layer-параметр нужно получить через checkout. Выбранное пользователем `<none>` может дать успешный checkout с нулевым указателем данных: это отдельное состояние, не обязательно ошибка вызова. [A2], `AE_Effect.h:1572–1586`

### Запрет анимации не равен запрету интерполяции

`PF_ParamFlag_CANNOT_TIME_VARY` запрещает изменение во времени. `PF_ParamFlag_CANNOT_INTERP` запрещает обычную интерполяцию, но оставляет дискретные изменения. Поэтому для параметра вроде постоянного размера сетки второй флаг не заменяет первый. Это непосредственно различающиеся описания в [A7:429–435].

### Изменение значения не равно обновлению интерфейса

`PF_Cmd_USER_CHANGED_PARAM` связан с контролами, использующими `PF_ParamFlag_SUPERVISE`. `PF_Cmd_UPDATE_PARAMS_UI` запрашивается флагом `PF_OutFlag_SEND_UPDATE_PARAMS_UI` и предназначен для допустимых UI-изменений. Header прямо запрещает ответ `PF_ChangeFlag_CHANGED_VALUE` из `UPDATE_PARAMS_UI`. [A1:1167–1193]

Следствие для проектирования: не прятать изменение алгоритмического состояния в косметическом обновлении панели. Серый контрол и сохранённое значение — разные наблюдения; один вид интерфейса не доказывает, какой вычислительный путь был исполнен.

## 6. Данные и владение

| Данные | Назначение | Граница |
|---|---|---|
| `global_data` | Данные глобального жизненного цикла эффекта | Настройка/завершение; не состояние одного кадра |
| `sequence_data` | Состояние применённого экземпляра | Нужны правила сериализации, восстановления и дублирования |
| `frame_data` | Classic frame-local данные | В header явно отделены от сохраняемых на диск данных |
| `pre_render_data` | Информация SmartFX-запроса | Передаётся в render и имеет отдельный delete callback |
| Входной/выходной world | Пиксели, предоставленные в рамках вызова | Не принадлежат пользовательскому `delete`/`free` |

Первые три строки основаны на [A3], SmartFX — на `AE_Effect.h:2501–2523,2565–2589`. Рекомендация для собственного кода: хранить вычислительный scratch локально, не превращать его в общий изменяемый cache без отдельного проекта владения и синхронизации.

Header отдельно предупреждает о lock-state `sequence_data`: обычно handle уже заблокирован хостом на время вызова; бездумная пара lock/unlock внутри реентерабельного кода может снять блокировку преждевременно. При первичном выделении в `SEQUENCE_SETUP` ситуация отличается. [A3:2858–2871]

## 7. Что показывает Skeleton — и чего он не показывает

Skeleton устанавливает `PF_OutFlag_DEEP_COLOR_AWARE` с комментарием про 16 bpc и выбирает `Iterate16Suite2` либо `Iterate8Suite2` по world. Это пример двух integer-путей, **не готовая float/SmartFX/MFR реализация**. [A4]

Также его catch перехватывает `PF_Err`, а не все возможные C++-исключения. Для собственного кода, добавляющего стандартные контейнеры или сторонние библиотеки, требуется отдельная защита ABI-границы: исключение не должно пересекать вызов хоста. Это наша инженерная рекомендация, а не заявление, что Skeleton уже решает все варианты ошибок.

## 8. От контракта к собственному продукту

### Одна identity-таблица для Minimal Gain

| Изменение | Где менять согласованно | Что не менять случайно |
|---|---|---|
| Название нового продукта | `PF_REGISTER_EFFECT`, PiPL Name, bundle metadata | Match name существующего shipping effect |
| Обработчик | `EffectMain` declaration/definition, export, PiPL code property | ABI arguments/ calling convention |
| Версия продукта | `PF_VERSION` в GlobalSetup и AE_Effect_Version PiPL | SDK protocol version в AE_EffectVers.h |
| Capabilities | GlobalSetup flags и corresponding PiPL flags | Не ставить MFR/float flags без реализации |
| Новое сохраняемое поле | Parameter disk ID / arbitrary wire schema | Старые IDs и прежний смысл значений |

Minimal Gain сейчас не использует sequence или arbitrary data: Gain — обычный
анимируемый slider, scratch `GainInfo` существует в render call. Добавлять persistence
лишь ради наличия struct не нужно. Для составного состояния см.
[arbitrary walkthrough](02-PARAMETERS-UI.md).

Для чтения SDK эта глава даёт проверенную карту команд и структур: **SDK-CONTRACT-REVIEWED / RUNTIME-NOT-CLAIMED**. Если разработчик превращает Minimal Gain в свой плагин, сборка, согласование ресурсов/экспортов, загрузка и пиксельные проверки дают доказательства именно для его артефакта и целевой среды. Они не являются условием редакционной готовности главы. Переход к областям и float: [SmartFX](03-SMARTFX.md); к данным глубины, ID и нормалей: [дополнительные каналы](08-AUXILIARY-CHANNELS.md).
