# SmartFX: зависимости, области и время жизни буферов

**Основа:** присланный SDK 25.6 build 61. Разобраны `AE_Effect.h` и официальный `SmartyPants.cpp`; новые сборка и запуск AE в этой редакционной итерации не выполнялись. [Идентичность источников](../18-SDK-HEADER-TOOLS/05-SUPPLIED-SDK-25.6.md).

SmartFX разделяет описание нужных входов и получение их пикселей. Это интерфейс взаимодействия с AE, а не обещание автоматически ускорить любой алгоритм. Уменьшение работы возможно только тогда, когда эффект корректно описывает зависимости и области. Первая часть следует из объявлений ниже; оценка ускорения требует измерения конкретного эффекта.

## 1. Два этапа и два разных `extra`

```text
PF_Cmd_SMART_PRE_RENDER → PF_PreRenderExtra
  прочитать output_request
  описать требуемые входы через checkout_layer
  вернуть result_rect / max_result_rect
  при необходимости передать принадлежащий запросу snapshot

PF_Cmd_SMART_RENDER → PF_SmartRenderExtra
  получить входные pixels по ранее заданным checkout IDs
  получить output world
  исполнить алгоритм в фактическом формате/размере
  завершить временное владение ресурсами
```

В `PF_PreRenderExtra` есть `input`, `output` и `cb`. В `PF_SmartRenderExtra` — `input` и `cb`, но нет такого же `output`-поля: выходной world получается через `checkout_output`. Копировать cast или доступ к полям между этими двумя структурами нельзя. [S1:2557–2595]

`PF_PreRenderInput` и `PF_SmartRenderInput` содержат `bitdepth`, запрос, GPU-контекст и индекс устройства. Значение в input описывает текущий вызов, а не все поддержанные вашим эффектом режимы. [S1:2493–2499,2565–2572]

## 2. Что именно означает запрос

`PF_RenderRequest` содержит прямоугольник `rect`, `field`, маску ARGB и `preserve_rgb_of_zero_alpha`. Служебные поля `unused`/`reserved` должны оставаться нулевыми. SmartyPants начинает с копии входного `output_request`, а не с случайно неинициализированной структуры. [S1:2484–2491], [S3:334]

Если эффект меняет только один канал, это ещё не означает, что ему не нужна alpha. Например, способ обработки прозрачных пикселей может зависеть от неё. SmartyPants явно добавляет `PF_ChannelMask_ALPHA` при соответствующем выборе и устанавливает сохранение RGB при нулевой alpha. Это поведение данного примера, не обязательный шаблон для всех эффектов. [S3:368–384]

**Практическое правило:** сначала определить математическую зависимость результата от входа, затем описывать запрос. Не убирать из запроса компоненты только ради предполагаемой экономии.

## 3. Три прямоугольника, которые нельзя смешивать

| Значение | Смысл по header |
|---|---|
| `input->output_request.rect` | Область результата, запрошенная хостом |
| `result_rect` | Область, действительно доступная для данного запроса; может быть пустой |
| `max_result_rect` | Максимальная область результата при запросе всего изображения; не должна меняться в зависимости от размера текущего запроса |

Последнее ограничение написано непосредственно рядом с `PF_PreRenderOutput.max_result_rect`. Если вычислять его просто как текущий маленький ROI, описание эффекта станет зависеть от того, какую часть кадра запросили. [S1:2511–2534]

Для эффекта без изменения геометрии можно начать с переноса областей, полученных от входа. Именно так SmartyPants объединяет `in_result.result_rect` и `in_result.max_result_rect` с выходными областями. Но это не универсальная формула для blur, glow или warp: у них могут отличаться требуемые входные пиксели и область возможного результата. [S3:386–397]

**Пример проектирования, а не код Adobe:** фильтру с радиусом 8 вокруг запрошенного пикселя обычно нужны соседние входные пиксели. Сначала определить пространство координат, текущий масштаб и граничную политику, затем расширять входной запрос. Нельзя механически расширять одновременно все прямоугольники на одинаковое число и считать ROI решённым.

`ref_width`/`ref_height` в `PF_CheckoutResult` описывают исходный размер слоя с оговорками header, а не автоматически размер выделенного буфера. Для обхода памяти нужны фактические размеры и stride полученного world. [S1:2525–2534], [S5]

## 4. Индекс параметра и checkout ID

В `checkout_layer` отдельно передаются `index` и `checkout_idL`. Первый указывает слой-параметр: 0 — основной вход, далее дополнительные параметры. Второй выбирает эффект; header требует неотрицательное уникальное значение. В `checkout_layer_pixels` затем передаётся именно этот ID. [S1:2537–2547,2574–2579]

Например, для временного эффекта два запроса одного входного слоя в разные моменты — две зависимости с разными IDs. Нельзя считать, что ID всегда равен индексу слоя: SmartyPants использует равные значения для своего простого случая, но структура API разделяет эти роли.

Вместе с запросом передаются `what_time`, `time_step`, `time_scale`. Их нельзя заменять округлённым номером кадра без определения временного контракта. Для воспроизводимого описания сохранять исходные целочисленные значения и масштаб времени. [S1:2539–2547]

## 5. Snapshot между этапами

`PF_PreRenderOutput` допускает `pre_render_data` и `delete_pre_render_data_func`. В render передаётся указатель из этого поля, а освобождение предусмотрено отдельным callback. [S1:2501,2520–2521,2568]

Для собственного эффекта удобно подготовить компактный неизменяемый snapshot: вычисленные коэффициенты, выбранную ветку алгоритма, список checkout IDs. Это рекомендация Библии. Нельзя сохранять туда адрес локальной переменной PreRender, указатель на уже возвращённый хосту параметр или буфер после checkin.

Не освобождать переданный snapshot «заодно в конце render» и одновременно через delete callback: получится два владельца. При ошибке до передачи данных ответственность за ещё не переданное выделение остаётся у вашего кода. Точный путь отмены и освобождения проверяется отдельным lifecycle-тестом; наличие поля в header не является таким тестом.

## 6. Освобождение: здесь четыре разных контракта

| Что было получено | Завершение использования |
|---|---|
| Параметр через `PF_CHECKOUT_PARAM` внутри `SMART_PRE_RENDER` | SmartyPants специально документирует автоматический checkin со стороны AE в этой фазе [S3:399–403] |
| Параметр через `PF_CHECKOUT_PARAM` внутри `SMART_RENDER` | SmartyPants явно вызывает `PF_CHECKIN_PARAM` и сохраняет cleanup при ошибке [S4:965–989] |
| World через `checkout_layer_pixels` | Указатель действителен до конца текущей команды или раннего checkin; `checkin_layer_pixels` позволяет раньше освободить память и помечен в header как необязательный [S1:2576–2583] |
| Auxiliary chunk через `PF_CheckoutLayerChannel` | Требуется `PF_CheckinLayerChannel`; это другой интерфейс, его правило нельзя заменять предыдущим [глава о каналах](08-AUXILIARY-CHANNELS.md) |

Именно поэтому обобщение «любой checkout всегда одинаково проверяется обратно» недостаточно для учебника. Равным образом неверно «SmartFX сам освободит вообще всё». Сначала определить конкретную функцию и фазу вызова.

Даже при удобном RAII helper необходимо сохранить обе ошибки: основную и cleanup. Ошибка освобождения не должна затереть первопричину или исчезнуть за статусом «канал недоступен». Это рекомендация для организации ошибок; она не меняет интерфейс Adobe.

## 7. Реальный формат пикселей

`PF_Pixel8`, `PF_Pixel16` и `PF_PixelFloat` — разные структуры. У них разный размер компонента, а порядок полей начинается с alpha. `PF_EffectWorld` содержит `rowbytes`, ширину, высоту и указатель данных. [S5]

Нельзя интерпретировать float world как `PF_Pixel8*`, а затем заявлять поддержку 32 bpc. Нельзя также вычислять переход между строками только как `width * sizeof(pixel)` вместо предоставленного stride. Это прямые следствия различающихся структур; корректность собственного обхода всё равно требует тестов на реальные размеры, padding и области.

Политику для отрицательных и HDR-значений нужно определить отдельно от структуры хранения. Если алгоритм обрезает результат в 0–1, это часть его поведения, а не неизбежное свойство float. Сравнение экспорта с image world требует учёта следующей обработки: файл на диске не обязательно является побайтовым дампом входа плагина.

## 8. Cache: зависимость должна быть видимой

В PreRender SmartyPants использует `GuidMixInPtr`, чтобы учитывать цвет фона композиции. В примере есть явная оговорка: этот участок не обрабатывает collapsed-comp случай. Поэтому нельзя переносить его в учебник как готовую универсальную cache invalidation. [S3:337–363]

Подход для собственной реализации: перечислить внешние зависимости, получить воспроизводимое представление их значений и использовать поддержанный механизм смешивания. Адрес объекта или неинициализированный padding не являются хорошим представлением содержимого. Это проектная рекомендация; конкретная схема должна пройти проверку изменения результата после изменения зависимости.

## 9. SmartFX, float, GPU и MFR — не один флаг

В [S2] отдельно определены `PF_OutFlag2_SUPPORTS_SMART_RENDER`, `PF_OutFlag2_FLOAT_COLOR_AWARE`, `PF_OutFlag2_SUPPORTS_GPU_RENDER_F32` и `PF_OutFlag2_SUPPORTS_THREADED_RENDERING`. Объявление одной возможности не подтверждает остальные.

Для GPU header дополнительно требует `PF_RenderOutputFlag_GPU_RENDER_POSSIBLE` на pre-render этапе. Само наличие поля `what_gpu` или настройка GPU у проекта не доказывает исполнения GPU-ветки конкретного эффекта. [S1:2504–2507], [S2:1007]

План Библии сохраняет отдельные проверки: CPU-корректность, float, частичные области, ошибки/отмена, cache и конкуренция. **В этой главе проверены источники интерфейса; готовность SmartFX Copy внутри AE остаётся незакрытым этапом 5.**
