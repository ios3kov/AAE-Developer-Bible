# Параметры и интерфейс Effect-плагина

Основа главы — **приложенный SDK 25.6 build 61**. Точные файлы, хэши и выявленные расхождения перечислены в [реестре сверки](../18-SDK-HEADER-TOOLS/06-PARAMETERS-PIXELS-SDK25.6.md). Пути `Headers/`, `Util/`, `Template/`, `Effect/`, `UI/` ниже отсчитываются от `Examples/` этой поставки.

**Значение параметра, возможность его анимировать и внешний вид контрола — три разных контракта.** Серый checkbox не означает, что его сохранённое значение обнулено; запрет интерполяции не означает запрета ключей; кнопка не заменяет хранилище результата операции. Это различия, которые нужно определить до написания UI.

Уровень главы — чтение SDK и рекомендации проектирования. Учебные фрагменты не являются собранным плагином; UI, undo и открытие старых проектов в этой итерации не проверялись.

## 1. Из чего состоит параметр

`PF_ParamDef` содержит описание типа, `flags`, `ui_flags`, имя и union значений. Поле `uu` само является union: во время добавления используется `uu.id`, а при сообщении об изменении значения — `uu.change_flags`. Не записывайте одновременно оба смысла в одну структуру. Точный layout: `Headers/AE_Effect.h:2406–2427`.

Параметр 0 — входной слой эффекта; его не надо добавлять как собственный slider. Остальные параметры объявляет плагин. Контракт вызова `PF_Cmd_RENDER` описан в `AE_Effect.h:3174–3197`.

| Идентификатор | Для чего нужен | Практическое правило Библии |
|---|---|---|
| Индекс в `params[]` | Найти параметр в текущей раскладке | Enum индексов должен совпадать с порядком добавления |
| `uu.id` при setup | ID, переданный при регистрации параметра | Выделять отдельные постоянные IDs; не отдавать старый ID новому смыслу |
| Имя контрола | Текст интерфейса | Не использовать локализованный текст как ключ собственной модели |
| Индекс варианта popup | Выбрать режим | Явно сопоставлять номер режиму; учитывать сохранённые старые значения |

Отдельные enums индексов и disk IDs показаны в `Template/Skeleton/Skeleton.h:77–87`; `Util/Param_Utils.h:70–84` записывает ID в `def.uu.id`, а параметр добавляет в конец. Стабильность IDs и проверка миграций — проектные правила Библии, а не обещание, что один ID автоматически исправит любую перестановку типов и значений.

## 2. Добавление: только setup, известный порядок, чистая структура

`PF_ADD_PARAM` используется при `PF_Cmd_PARAMS_SETUP`; комментарий разрешает добавление в конец именно на этой фазе (`AE_Effect.h:2675–2680`). Не создавайте новые параметры из render или при каждом раскрытии панели.

Рекомендуемый порядок работы: заранее определить индексы и IDs, очистить `PF_ParamDef`, заполнить нужный тип, проверить возврат добавления и установить `out_data->num_params` с учётом входного слоя. `Skeleton.cpp:85–118` показывает эту последовательность.

### Пример: число колонок без анимации, сила эффекта с анимацией

Это авторский учебный фрагмент для окружения Skeleton с подключёнными SDK headers и `Param_Utils.h`. Он описывает только setup, не регистрацию PiPL, render или миграцию ранее выпущенного эффекта.

```cpp
enum ParamIndex {
    kInput = 0,
    kColumns,
    kAmount,
    kNumParams
};
enum ParamDiskId {
    kColumnsId = 1001,
    kAmountId = 1002
};

PF_Err DefineParameters(PF_InData* in_data, PF_OutData* out_data)
{
    if (!in_data || !out_data) return PF_Err_BAD_CALLBACK_PARAM;
    PF_ParamDef def;

    AEFX_CLR_STRUCT(def);
    def.flags = PF_ParamFlag_CANNOT_TIME_VARY;
    PF_ADD_SLIDER("Columns", 1, 64, 1, 16, 4, kColumnsId);

    // Этот макрос сам очищает def; flags передаётся аргументом.
    PF_ADD_FLOAT_SLIDERX("Amount", 0.0, 4.0, 0.0, 1.0, 1.0,
                        PF_Precision_HUNDREDTHS, 0,
                        PF_ParamFlag_NONE, kAmountId);

    out_data->num_params = kNumParams;
    return PF_Err_NONE;
}
```

`PF_ADD_SLIDER` возвращает ошибку из окружающей функции при неудачном добавлении. Он **не** очищает всю структуру; `PF_ADD_FLOAT_SLIDERX`, напротив, очищает её и затем присваивает переданные flags. Флаг, выставленный перед вторым макросом, не сохранится сам собой. См. `Param_Utils.h:70–84,122–149`.

Выбор 1…64, удобной шкалы 1…16 и default=4 здесь принадлежит примеру. Это не ограничения Adobe на размер сетки.

## 3. Анимация и интерполяция

`AE_Effect.h:423–456,472–488` разделяет следующие признаки:

| Флаг | Документированный смысл | Чего он не делает |
|---|---|---|
| `PF_ParamFlag_CANNOT_TIME_VARY` | Значение нельзя менять во времени; keyframe-контрол не появляется | Не делает сам UI серым |
| `PF_ParamFlag_CANNOT_INTERP` | Значения не интерполируются непрерывно | Не запрещает дискретные изменения во времени |
| `PF_ParamFlag_SUPERVISE` | Запрашивает `PF_Cmd_USER_CHANGED_PARAM` при пользовательском изменении | Не превращает UI callback в render callback |
| `PF_PUI_DISABLED` | Делает UI параметра недоступным, серым | Сам по себе не определяет новое значение и алгоритм рендера |

Последний флаг относится к `ui_flags`, не к `flags` (`AE_Effect.h:2341–2369`).

**Правило проектирования:** размер сетки, который не должен меняться между ключами деформации, объявлять неанимируемым, а не просто дискретным. Отключение интерполяции оставляет возможность скачка топологии. Изменение такого контракта в уже выпущенном плагине требует отдельной проверки старых проектов с ключами; новый флаг не является доказанной миграцией.

## 4. Текущее значение, default и шкала — не одно число

У float-slider есть `value`, `dephault`, `valid_min/max`, `slider_min/max`, `precision` и `display_flags`. `value` объявлен как `PF_FpLong`, границы/default — как `PF_FpShort`; `precision` задаёт число показываемых десятичных знаков, а не новый тип хранения (`AE_Effect.h:1757–1780`).

В примере Amount можно ввести до 4.0, хотя ширина ползунка представляет 0…1. Видимая шкала не является полной областью допустимого ввода. Если алгоритм имеет дополнительные ограничения — например, ненулевой знаменатель или целое число элементов, — проверяйте их на границе вычислительного ядра, а не полагайтесь только на оформление UI.

Для совместимости с проектами, где нового параметра ещё не было, существует `PF_ParamFlag_USE_VALUE_FOR_OLD_PROJECTS`: поле `value`, переданное при setup, инициализирует отсутствующий старый параметр; `dephault` сохраняет значение для нового применения или Reset. Флаг не действует для `PF_Param_LAYER` (`AE_Effect.h:449–458`). Макросы slider обычно задают value и default одинаково; для двух разных значений нужно явное заполнение до добавления, а не изменение после него.

`PF_ValueDisplayFlag_PIXEL` представляет внутренние 0…1 как шкалу пикселя; комментарий прямо сохраняет value в 0…1. `PF_ValueDisplayFlag_REVERSE` меняет знак представления. Это не повод повторять преобразование внутри render. См. `AE_Effect.h:1683–1693`.

## 5. Две команды UI, два разных назначения

### USER_CHANGED_PARAM: пользователь совершил действие

Для supervised-параметра extra указывает на `PF_UserChangedParamExtra`; `param_index` сообщает, какой контрол изменён. Разрешено менять значения других параметров и отмечать изменённые параметры `PF_ChangeFlag_CHANGED_VALUE` (`AE_Effect.h:1167–1179,2376–2384`). SDK описывает такие изменения как undo/redo-операции.

Пример замены пресета: обработчик получает индекс popup, вычисляет новый цвет, меняет **параметр цвета**, отмечает его change flag. Дальнейший render читает параметр цвета, а не случайное значение из UI-памяти. Соответствующее направление работы видно в `UI/Supervisor/Supervisor.cpp:488–525`; это разбор источника, не сообщение об успешном запуске образца.

### UPDATE_PARAMS_UI: привести внешний вид к текущим значениям

Эта команда запрашивается флагом `PF_OutFlag_SEND_UPDATE_PARAMS_UI` в global setup. Она может приходить при открытии Effect Controls или смене времени. Разрешены косметические обновления, **не** `PF_ChangeFlag_CHANGED_VALUE` (`AE_Effect.h:1181–1193`).

Поэтому нельзя делать так: «панель открылась — переписали цвет, сбросили ключи, починили значения render». Оформление должно отражать состояние эффекта, а не становиться скрытым условием его вычисления.

## 6. Как корректно включить или отключить контрол

`PF_ParamUtilsSuite3::PF_UpdateParamUI` принимает effect reference, индекс и указатель на описание. В разрешённом списке есть `PF_PUI_DISABLED`, размер UI, имя, collapse-twirly и поля отображения slider. Эти изменения косметические и не попадают в undo (`AE_EffectSuites.h:203–242`).

Для обычного числового параметра можно передать копию определения и изменить только нужный UI-флаг. Пример предполагает уже успешно полученную `PF_ParamUtilsSuite3`; приобретение/освобождение suite остаётся обязанностью вызывающего кода.

```cpp
PF_Err SetNumericControlEnabled(PF_ParamUtilsSuite3* ui,
                               PF_ProgPtr effect_ref,
                               PF_ParamIndex index,
                               const PF_ParamDef& current,
                               bool enabled)
{
    if (!ui) return PF_Err_BAD_CALLBACK_PARAM;
    PF_ParamDef display = current;
    if (enabled) display.ui_flags &= ~PF_PUI_DISABLED;
    else         display.ui_flags |=  PF_PUI_DISABLED;
    return ui->PF_UpdateParamUI(effect_ref, index, &display);
}
```

Вызывать этот фрагмент следует из разрешённых USER_CHANGED_PARAM/UPDATE_PARAMS_UI, не из render. Простое копирование структуры здесь достаточно потому, что меняется скалярный флаг: это **не** deep-copy произвольных handles или строк. Не освобождайте данные, которыми владеет исходный параметр.

В `Supervisor.cpp:557–601` есть копирование перед изменением UI; строка непосредственного отключения popup в данном образце закомментирована. Не выдавайте комментарий «disable» за реально исполняемое отключение.

### Hidden и disabled

`PF_PUI_NO_ECW_UI` скрывает элемент Effect Controls, но в AE не скрывает ключи Timeline. `PF_PUI_INVISIBLE` в enum описан как скрывающий обе области; его динамическое изменение через данный UI-контракт ограничено оговоркой о Premiere. `PF_UpdateParamUI` не является универсальным setter любого бита. `Supervisor.cpp:619–630` отдельно использует AEGP stream API для динамического скрытия; это другой механизм с другим владением ресурсами. Источники: `AE_Effect.h:2313–2321,2349–2366`; `AE_EffectSuites.h:212–222`.

## 7. UI-only контрол и настоящая кнопка

`PF_PUI_STD_CONTROL_ONLY` означает отсутствие связанного data stream и ключей. SDK требует сочетания с `PF_ParamFlag_SUPERVISE`, чтобы действие можно было обработать. Это подходит, например, для команды, меняющей другие параметры или arbitrary data, но не даёт самостоятельного хранилища результата (`AE_Effect.h:2279–2310`).

Для momentary button есть отдельный тип `PF_Param_BUTTON`; его поле value в этой поставке помечено как неиспользуемое. `PF_ADD_BUTTON` принимает раздельно `PUI_FLAGS` и `PARAM_FLAGS`, очищает структуру и назначает подпись кнопки (`AE_Effect.h:1894–1906`; `Param_Utils.h:188–199`). `Paramarama.cpp:174–178` передаёт `PF_ParamFlag_SUPERVISE`.

**Правило Библии:** действие «сбросить сетку» обрабатывает button event, а сама сетка хранится в документированном состоянии эффекта. Сохранять «кнопка нажата» вместо результата операции — другая, обычно неверная модель.

В `AE_Effect.h:2383–2384` для обновления STD_CONTROL_ONLY сделано исключение из change-flag механизма. Не переносите правила обычного сохраняемого slider на UI-only контрол автоматически.

## 8. Параметры читаются в нужный момент, не через UI

В классическом `PF_Cmd_RENDER` обычные параметры уже содержат значение текущего времени. Дополнительные layer-параметры и значения на другом времени требуют checkout. Предоставленный checkout объект должен находиться вне `params[]`; после использования он возвращается через checkin и больше не читается (`AE_Effect.h:2652–2673,3187–3202`). SmartFX имеет дополнительные правила фаз; они вынесены в [главу SmartFX](03-SMARTFX.md).

Особенно важны два ограничения из присланной поставки:

- Checkout layer внутри UPDATE_PARAMS_UI возвращает чёрные пиксели вместо обычного render, чтобы не вызвать render/deadlock (`AE_Effect.h:2664–2667`). Это не проверка отсутствия картинки или auxiliary-канала.
- `PF_GetCurrentState` в контексте UPDATE_PARAMS_UI описан как возвращающий случайное состояние (`AE_EffectSuites.h:244–245`). Его нельзя использовать здесь как надёжный признак изменения изображения.

**Вывод проектирования:** UI-команды не служат скрытым считывателем render-данных. Значения вычислительного ядра формируются в подходящей фазе; «панель была открыта» не должно быть зависимостью изображения.

## 9. Point, popup и строки: частые ошибки единиц

У `PF_Param_POINT` текущие координаты заданы в координатах источника от левого верхнего угла и имеют fixed-point представление. Default задаётся в процентах, также fixed-point. Для `PF_Param_POINT_3D` default=50 означает середину, не 0.5; default Z выражен через высоту слоя (`AE_Effect.h:1828–1873`). Перенос «50 процентов» напрямую как «50 пикселей» ошибочен.

Popup хранит value и количество вариантов, а строка списка использует `|`. В учебных образцах первый вариант обозначен 1 (`AE_Effect.h:1875–1891`; `Paramarama.cpp:139–143`). Разделяйте номер варианта и индекс параметра.

Используйте `PF_DEF_NAME`, `PF_DEF_NAMEPTR`, `PF_DEF_NAMESPTR`, а не внутренние имена полей. Для pointer-полей SDK требует стабильные строки (`AE_Effect.h:1698–1711`). Указатель на временную строку, исчезающую после callback, не является стабильной строкой.

## 10. Где нужен Drawbot, а где стандартный UI

**Рекомендация Библии:** начинать со стандартных параметров, если задача выражается slider/checkbox/color/popup/layer/button. Overlay, ручки деформации и собственное рисование требуют отдельной системы событий, а не переименования обычного slider.

`PF_PUI_TOPIC`/`PF_PUI_CONTROL` запрашивают соответствующие области custom UI и требуют `PF_OutFlag_CUSTOM_UI` (`AE_Effect.h:2260–2277`). `ColorGrid.cpp:487–496` отделяет DRAW от действий пользователя. `ColorGrid_UI_Handler.cpp:286–333,441–474` показывает получение drawing reference, работу через Drawbot suites и их освобождение. Это маршрут изучения образца, не готовая универсальная UI-библиотека.

Проектируйте разделение: ввод меняет согласованную модель; draw только показывает её; render использует снимок параметров нужного времени. Тяжёлые вычисления, загрузку файлов и перестройку проекта не стоит прятать в draw event. Технология большой панели выбирается отдельно в [разделе Panels](../07-PANELS/README.md), с проверкой поддержки целевым AE; наличие технологии в других Adobe-приложениях не доказывает её поддержку здесь.

## 11. Не копировать образцы без чтения

В этой поставке найдено несовпадение порядка enum индексов `Paramarama.h:74–85` с порядком добавления checkbox/angle/popup в `Paramarama.cpp:123–143`. У Supervisor есть изменения popup-полей вне перечисленного whitelist `PF_UpdateParamUI`. Эти расхождения [сохранены в реестре](../18-SDK-HEADER-TOOLS/06-PARAMETERS-PIXELS-SDK25.6.md), а не молча перенесены как гарантии SDK. Ни один из них не объявлен runtime-дефектом без запуска.

## 12. Приёмка параметров будущего плагина

Это перечень необходимых проверок, **не выполненные в этой редакционной итерации тесты**.

Проверить новое применение и Reset отдельно от открытия проекта старой версии; минимальные/максимальные вводимые значения отдельно от шкалы; сохранение IDs и типов; наличие/отсутствие ключей; undo/redo supervised-операций; изменение времени при открытой и закрытой панели. Проверить UI-only действия и сохранённый результат, а не только внешний вид кнопки. Для point-параметров нужны разные размеры источника; для custom UI — события, координаты и масштаб интерфейса.

На каждый PASS требуются конкретный build, проект и наблюдение. Исходный header подтверждает контракт, но не то, что конкретный плагин правильно его реализовал.

## 13. Сохраняемое состояние и arbitrary data {#13-сохраняемое-состояние-и-arbitrary-data}

Проверено 2026-10-07 по SDK 25.6 build 61: `Headers/AE_Effect.h:1961–2169`
(`PF_ArbitraryDef`, `PF_ArbParamsExtra`), `UI/ColorGrid/ColorGrid.h` и
`ColorGrid_Arb_Handler.cpp`. Это SDK-CONTRACT-REVIEWED; исполнение в AE не заявлено.
Arbitrary parameter нужен для составного пользовательского значения, которому
недостаточно обычных sliders/points. Это не способ спрятать несериализуемый cache.

| Хранилище | Пример | Правило |
|---|---|---|
| Обычный parameter stream | Amount с ключами | Host хранит значения и анимацию; читать на нужном времени |
| Arbitrary parameter | Набор контрольных точек | Effect предоставляет операции копирования, сравнения, persistence и интерполяции |
| Sequence state | Восстанавливаемая конфигурация экземпляра | Отдельный lifecycle flatten/resetup; не подмена анимируемого stream |
| Transient cache/scratch | Таблица выборки для данного кадра | Пересоздаваемый результат; не сериализовать в project |

`PF_ArbitraryDef.id` различает arbitrary types эффекта и **не равен disk ID**
из `PF_ParamDef.uu.id`. При ADD_PARAM `dephault` переходит host, `value` передаётся
NULL; во время render `value` принадлежит host. Сначала проверять
`PF_Cmd_ARBITRARY_CALLBACK`, затем `PF_ArbParamsExtra.which_function` и `id`,
и только после этого нужную ветку union. Header comment ошибочно употребляет
plural `PF_Cmd_ARBITRARY_CALLBACKS`; реальный enum — singular.

| Selector | Операция и владение | Failure policy собственной реализации |
|---|---|---|
| `PF_Arbitrary_NEW_FUNC` | Выделить и заполнить новый handle через `new_func_params.arbPH` | Не публиковать частично созданный объект |
| `PF_Arbitrary_DISPOSE_FUNC` | Освободить переданный allocated value | Не трогать соседние host values/refcon |
| `PF_Arbitrary_COPY_FUNC` | Deep-copy borrowed `src_arbH`; новый `dst_arbPH` принадлежит caller | Ошибка allocation не меняет источник |
| `PF_Arbitrary_FLAT_SIZE_FUNC` | Вернуть число bytes | Проверить overflow до вычисления длины |
| `PF_Arbitrary_FLATTEN_FUNC` | Записать в уже выделенный host buffer, соблюдая `buf_sizeLu` | Не писать вне buffer; не освобождать его |
| `PF_Arbitrary_UNFLATTEN_FUNC` | Validate bytes, выделить новый `arbPH` для caller | Reject unsupported/corrupt schema до публикации |
| `PF_Arbitrary_INTERP_FUNC` | Borrow left/right, создать новый `interpPH` | Не менять endpoints; velocity уже включена в `tF` |
| `PF_Arbitrary_COMPARE_FUNC` | Вернуть `PF_ArbCompareResult` | Сравнивать смысл, не адреса или padding |
| `PF_Arbitrary_PRINT_SIZE_FUNC` / `PRINT_FUNC` | Размер и bounded textual representation | Учесть terminator и print flags в собственной согласованной policy |
| `PF_Arbitrary_SCAN_FUNC` | Bounded parse `bytes_to_scanLu` → новый handle | Не искать terminator за размером input |

В compare comment указаны 0/1, но тип и enum включают EQUAL, LESS, MORE,
NOT_EQUAL. Использовать именованные constants и согласованную equality policy,
не объявлять комментарий единственным ordering contract. UI refs и refcon не
сериализуются. Для каждого allocated SDK handle требуется paired disposal; входные
handles и flat buffers остаются borrowed. Callback availability не разрешает
произвольные project mutations или thread access.

### Конкретная эволюция payload

[Portable codec](../16-WORKING-TEMPLATES/effect-state/README.md) хранит `BSTA`,
u16 little-endian version, length, Amount в тысячных и в v2 добавляет Mode.
v1 занимает 10 bytes, v2 — 12. Это авторская схема, не Adobe wire format.
Декодирование v1 добавляет Mode=0; truncated/invalid payload оставляет destination
неизменным; future version выдаёт unsupported. Adapter переводит ошибку в выбранный
SDK error и UI diagnostic, но не заменяет неизвестное состояние defaults молча.
`memcpy(sizeof(MyStruct))` непригоден для persistence: ABI padding, endian, pointers
и platform-size поля не являются схемой. Encode принимает уже валидированную модель.

Для набора точек интерполировать только одинаковую topology; разную topology
обрабатывать выбранной дискретной policy или запрещать interpolation соответствующим
parameter flag. Это product design, не автоматическая гарантия arbitrary API.
Сравнение должно учитывать все render-affecting fields; NaN нужно либо отвергать,
либо канонизировать по заранее выбранной policy.

### Migration и наблюдаемый результат

| Изменение продукта | Policy | Проверка продукта |
|---|---|---|
| Добавлен Mode | Новый disk ID; old-project value отдельно от Reset default | Старый project сохраняет прежнее изображение; Reset даёт новый default |
| Amount переставлен в UI | Сохранить disk ID и смысл | Ключи остаются Amount, не переходят другому контролу |
| Arbitrary schema v1→v2 | Decode v1, explicit migration, encode v2 | Save/reopen, duplicate, Undo сохраняют значение и анимацию |
| Неизвестный future schema | Не перезаписывать неизвестное состояние defaults | Явный unsupported diagnostic вместо тихой потери данных |
| Изменился sampling implementation | Не менять arithmetic/persistence незаметно | Legacy fixture + matched implementation comparison |

Дублирование должно давать независимые mutable values; cache не участвует в
семантическом compare. Восстановление sequence state строит новый runtime объект
из валидированной плоской модели, а не доверяет адресу из старого project. См.
[memory/flatten lifecycle](../01-ARCHITECTURE/02-MEMORY-THREADING-ERRORS.md).
