## FSTR Line — панель над состоянием After Effects

### Задача

Показывать обычные AE layers в компактном Track View, не становясь вторым владельцем проекта. В архитектурном документе источник истины — активная композиция AE; packing и временное состояние UI являются производными данными.

Источник: [ARCHITECTURE.md, Source of Truth / Data Flow / Architectural Boundaries](https://github.com/ios3kov/FSTR-Line/blob/c69e3663de59dc44cbdef18042891f6dd1ce5ee6/docs/ARCHITECTURE.md).

### Способ и зафиксированные результаты

Архитектура разделяет **UI → Timeline Core → Host Adapter → After Effects**. Core работает с нормализованными снимками и смысловыми командами без вызовов host API. Адаптер проверяет актуальность снимка, выполняет операцию в Undo Group и обновляет представление. Это архитектурный контракт проекта, а не доказательство атомарности любой операции в AE.

Отчёт разработки отдельно перечисляет реализованные snapshot/revision guards, отказ от устаревших команд, FakeHostAdapter, объединение запросов refresh, отбрасывание устаревших ответов и сохранение последнего корректного представления при ошибке. Он сообщает о локальных регрессиях Core/CEP до 45 тестов на разных этапах; повторного запуска этих тестов для данной главы нет.

Источники: [архитектурный контракт](https://github.com/ios3kov/FSTR-Line/blob/c69e3663de59dc44cbdef18042891f6dd1ce5ee6/docs/ARCHITECTURE.md), [отчёт состояния](https://github.com/ios3kov/FSTR-Line/blob/c69e3663de59dc44cbdef18042891f6dd1ce5ee6/docs/DEVELOPMENT-STATUS-2026-09-28.md).

### Неудачные попытки и что они действительно показывают

В [COMMAND-PROBE-RUNTIME-2026-09-28.md](https://github.com/ios3kov/FSTR-Line/blob/c69e3663de59dc44cbdef18042891f6dd1ce5ee6/docs/TEST_RECORDS/COMMAND-PROBE-RUNTIME-2026-09-28.md) сохранён эксперимент `runtime-20260928T184627Z`, build ID `20260928T184359Z-cf383a8-72414`.

После загрузки исправленного probe сценарий ExtendScript создал композицию и слой, изменил start/in/out, enabled, selection и время композиции. Новая запись command callback не появилась. Это **отрицательное наблюдение для конкретного сценария**, а не доказательство отсутствия всех способов уведомлений в AE.

Первый запуск с ошибкой `5027:47 Plugin ID is invalid` исключён самим отчётом: у probe была неверная сигнатура entry point. Исправленный вариант использовал пятиаргументную `AEGP_PluginInitFunc` и compile-time ABI assertion. Значение callback priority также расходилось с запрошенным; его смысл и момент вызова в отчёте оставлены для дальнейшей проверки.

Перетаскивание слоёв через native UI, native Undo/Redo, playhead и изменения из другого плагина в таблице этого эксперимента отмечены **NOT RUN**. Нельзя распространять отрицательный результат на эти сценарии.

### Ограничения

Согласно [отчёту разработки](https://github.com/ios3kov/FSTR-Line/blob/c69e3663de59dc44cbdef18042891f6dd1ce5ee6/docs/DEVELOPMENT-STATUS-2026-09-28.md), **SYNC-001 остаётся BLOCKED**. Полный поддерживаемый источник push-уведомлений не найден в рамках проведённого исследования. Polling, `Project.revision` и события самой панели не принимаются за выполнение именно этого требования проекта.

Не превращаем это ограничение конкретного исследования в утверждение о невозможности решения. Не называем Auto Sync завершённой event-based синхронизацией.

## AE Hot Loader — поздняя загрузка новых эффектов

### Задача

Загрузить и зарегистрировать **новый** native effect bundle в уже работающем AE. Пользовательский интерфейс проекта — ScriptUI-панель, внутренние компоненты — native helper и загрузчик.

Источник: [PRODUCTION_PLAN.md](https://github.com/ios3kov/AE-Hot-Loader/blob/cf338bcd861504d695c3181767c18bb423575814/docs/PRODUCTION_PLAN.md).

### Способ и зафиксированные результаты

[Протокол bridge](https://github.com/ios3kov/AE-Hot-Loader/blob/cf338bcd861504d695c3181767c18bb423575814/docs/BRIDGE_PROTOCOL.md) описывает `request.txt` / `response.txt`, версию сообщения и `request_id`. Панель пишет запрос, helper обрабатывает его из AE idle hook, ответ сопоставляется с запросом. Это PoC-протокол: его документ не доказывает надёжность при конкурирующих запросах или сбоях записи.

Журнал разработки описывает переход от сохранённого регистрационного callback к внутреннему пути `ML::LoadPlugins`. В записи **Stop Criterion A — PASSED — 2026-09-27** сообщается: новый bundle загружен без перезапуска AE, два диагностических эффекта зарегистрированы, появились в панели Effects & Presets, применились к слою, прошли RAM Preview и обычный рендер. Эффекты были pass-through.

Это **результат, сообщённый проектным журналом для AE 25.6.0 ARM64**. Здесь не выполнено независимое повторение и не опубликован новый отчёт пиксельной эквивалентности. Заголовок `PASSED` относится к описанному опыту; сам журнал далее задаёт интеграцию loader path в production Agent как следующий шаг. Не считаем полностью проверенным весь путь кнопки ScriptUI только из-за этого заголовка.

Источник: [хронология архитектуры и live-проверок](https://github.com/ios3kov/AE-Hot-Loader/blob/cf338bcd861504d695c3181767c18bb423575814/docs/PRODUCTION_PLAN.md).

### Неудачные попытки

Тот же журнал фиксирует три разных результата:

| Контекст опыта | Записанный результат | Граница вывода |
|---|---|---|
| AEGP idle hook из startup-контекста Effect | `-1102`; последующее разделение на AEGP Agent и Effect Bridge | Не обобщать на все способы взаимодействия Effect и AEGP. |
| Прямой поздний вызов сохранённого registration callback | `1`, non-success | Не присваивать этому коду универсальный смысл вне данного callback. |
| Поиск bridge по жёстко заданному пути | `-2002`; переход к поиску экспорта и фактически загруженного image | Документирует конкретную причину сбоя поиска, не совместимость любых установок. |

Для `ML::LoadPlugins` журнал также записывает return value `1`, но успешную регистрацию двух эффектов с результатами `0`. Поэтому одинаковое число из разных API нельзя автоматически интерпретировать одинаково.

Источник: [Architecture revision / bridge path lookup / Live internal-loader proof](https://github.com/ios3kov/AE-Hot-Loader/blob/cf338bcd861504d695c3181767c18bb423575814/docs/PRODUCTION_PLAN.md).

### Ограничения

**Поздняя загрузка нового bundle не равна замене уже загруженного плагина.** Описанный тест не подтверждает выгрузку старого кода, замену существующих экземпляров, перенос их состояния, работу с произвольными сторонними плагинами, MFR/GPU или другими версиями AE и Windows.

`ML::LoadPlugins` в источнике исследуется как внутренний путь AE, а не публичный стабильный SDK-контракт. Bible сохраняет его в исследовательском кейсе, но не делает обязательной частью безопасного установщика или обычных SDK-примеров. Полнота raw-логов, точная сборка тестового kit и переносимость должны быть проверены отдельным аудитом.

Источник границ опыта и следующего этапа: [PRODUCTION_PLAN.md](https://github.com/ios3kov/AE-Hot-Loader/blob/cf338bcd861504d695c3181767c18bb423575814/docs/PRODUCTION_PLAN.md).

## Формат дальнейших кейсов

Каждый перенос оформляется как **задача → способ → наблюдаемый результат → неудачные попытки → ограничения → код и коммит → доказательства проверки**.

До использования кода в эталонном примере фиксируем конкретный файл и коммит, проверяем относящиеся к нему тесты и происхождение материалов, записываем решение: переиспользовать / адаптировать / не переносить. Причина отказа тоже остаётся полезным результатом. Завершение обоих продуктов не является условием переноса отдельного проверенного решения.

Результаты исходного проекта поддерживают только заявленную в его записи область. После адаптации кода результат исходного проекта нельзя приписать новой реализации: для compiler/runtime утверждения нужны проверки её точного source/artifact identity и целевой среды. Перенос объяснения или SOURCE EXAMPLE может оставаться RUNTIME-NOT-CLAIMED. Неразрешённый SYNC-001 и исследовательский private loader сохраняют свои ограничения в закреплённых снимках.
