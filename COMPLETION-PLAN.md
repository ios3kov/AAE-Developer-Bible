# План доведения AE Developer Bible до готовой редакции

Дата фиксации: **2026-09-30**.  
Статус: **согласованный план доработки**.  
Фиксация этого документа не означает выполнения перечисленных этапов.

## Цель

**Разработчик берёт нужный раздел, собирает пример, запускает его в After Effects и получает описанный результат — без догадок и скрытых недоделок.**

Готовность определяется работающими примерами, воспроизводимыми проверками и согласованной документацией, а не количеством глав.

## Исходная точка

На момент согласования плана база имеет проверки синтаксиса SDK, но полноценные сборки, запуск примеров внутри AE и Windows-проверки ещё не подтверждены.

Актуальные ограничения и покрытие зафиксированы в:

- [STATUS.md](STATUS.md);
- [VERIFICATION.md](VERIFICATION.md);
- [FINAL-COVERAGE-AUDIT.md](FINAL-COVERAGE-AUDIT.md).

Например, Custom UI / Drawbot пока представлен каркасом без рисования, а несколько других направлений — подготовленными SDK-примерами без проверки внутри AE. Эти пробелы должны быть закрыты, а не переименованы в готовые реализации.

Подробный исполняемый чеклист: [COMPLETION-CHECKLIST.md](COMPLETION-CHECKLIST.md). Он является источником истины для закрытия этапов ниже.

## Практический опыт FSTR Line и AE Hot Loader

[Раздел 22 — практические кейсы](22-PROJECT-CASE-STUDIES/README.md) сохраняет результаты с привязкой к коммитам источников. Завершение обоих продуктов не требуется для переноса отдельного полезного решения. Исходные проекты продолжают развиваться независимо от Bible.

**FSTR Line:** разделение UI/Core/Host Adapter, нормализованные снимки, защита от устаревших команд, обработка refresh, FakeHostAdapter и ограниченный отрицательный результат command-hook probe. Полная синхронизация SYNC-001 не считается выполненной.

**AE Hot Loader:** протокол ScriptUI ↔ AEGP Agent, жизненный цикл helper, диагностика поиска загруженного модуля, неудачный поздний registration callback и сообщённый проектным журналом опыт поздней загрузки новых тестовых эффектов через внутренний loader. Такой опыт не доказывает замену уже загруженного плагина и не превращает private API в стабильный SDK-контракт.

До создания новых примеров этапов 5–6 выполняем аудит кандидатов. Формат переноса:

```text
Задача → способ → наблюдаемый результат → неудачные попытки
→ ограничения → код и коммит → доказательства проверки
```

Для каждого кандидата записываем решение: **переиспользовать / адаптировать / не переносить**, причину и целевой раздел Bible. Различаем исходный отчёт и независимое повторение теста. Проверка в одном проекте не закрывает host-gate другого автоматически; после адаптации кода нужны проверки самой Bible.

Публикация первичных кейсов не закрывает этап 3A. Его критерий — законченный аудит кандидатов и решений о переносе, а не завершение продуктов, SYNC-001 или production hot reload. Исследовательские результаты остаются в разделе 22 и не становятся скрытой зависимостью безопасного установщика или обычных SDK-примеров.

## Разбор всех эффектов остаётся обязательным

Исследовательский атлас не исключается из объёма готовой библии и не заменяется несколькими демонстрационными разборами.

Продолжает действовать [утверждённый план исследования штатных и bundled-эффектов](21-BUILTIN-EFFECTS-REVERSE-ENGINEERING/EXECUTION-PLAN.md):

```text
Карта установки
→ анализ реализации
→ контролируемые эксперименты
→ восстановление алгоритма
→ независимые примеры
→ проверка и документирование результата
```

Каталог: [MASTER-EFFECT-LIST.md](21-BUILTIN-EFFECTS-REVERSE-ENGINEERING/MASTER-EFFECT-LIST.md).

Порядок платформ: **macOS, затем Windows**. Соответствие реализации между платформами не предполагается без проверки.

Найденный адрес функции не означает восстановленного алгоритма. Для `3D Channel Extract` необходимо исследовать не только две именованные функции `RenderX`, но и встроенную в `FilterMain` 32-битную ветку. Текущий ориентир — [карта функций и диспетчеризации](21-BUILTIN-EFFECTS-REVERSE-ENGINEERING/3D-Channel/3D-Channel-Extract/FILTERMAIN-FUNCTION-MAP-MACOS-AE25.6.md).

### Выпуск 1 — проверенная практическая часть

Рабочие примеры, инструкции и тесты практической части подтверждены на согласованной матрице. Инструменты безопасны, документация согласована, ограничения явно перечислены. Аудит существующих проектов из этапа 3A выполнен; незавершённость исходных продуктов не подменяет и не блокирует проверку независимых практических примеров.

**Этот выпуск не является завершением всей библии.** Исследовательский атлас сохраняется в обязательном объёме дальнейших работ.

### Выпуск 2 — полная согласованная редакция с атласом

Завершена практическая часть и весь согласованный каталог исследований. Для каждого эффекта выполнены критерии разбора из исследовательского плана; доказанные факты, реконструкции и оставшиеся неизвестные явно разделены.

Все обязательные сценарии проверены, блокирующие ошибки закрыты, выпуск воспроизводится из зафиксированной версии репозитория.

## Как принимать работу

Каждая задача проходит цепочку:

```text
Изменение
→ проверка
→ ревью
→ отчёт
→ фиксация в Git
```

В отчёте указываются версии AE, SDK, ОС и архитектуры, команды проверки, наблюдаемый результат и ограничения. Статус этапа изменяется только при наличии результатов, подтверждающих его критерий завершения.

Исследовательские уровни доказательств **DOCUMENTED / PROVEN / OBSERVED / RECONSTRUCTED / UNKNOWN** сохраняются отдельно от статуса работоспособности примеров. Принятое компилятором объявление не означает успешной загрузки или корректного рендера внутри AE.

Проверки внутри AE выполняются на машинах с установленными AE и SDK, пакетами, а не десятками ручных команд. **Непроведённый обязательный тест остаётся незакрытой задачей.** Зелёная проверка документации не заменяет проверку плагина в AE.

## Ближайший приоритет

Сначала исправить безопасную работу инструментов и согласовать документацию. Перед созданием новых примеров провести аудит FSTR Line и AE Hot Loader по этапу 3A; использовать подходящие наработки, а не переписывать их без проверки. Затем довести три эталонных примера — **Minimal Gain, SmartFX Copy и AEGP MenuTool** — до полного цикла:

```text
Сборка → установка → запуск в AE → проверка результата
```

Этот проверенный образец используется для остальных разделов. Количество новых глав само по себе не считается прогрессом готовности.
